# Prioritized measured expansion

| Priority | Work | Acceptance gate |
|---|---|---|
| P0 | Untouched forward forecast collection with actual event/receipt timestamps | Immutable data versions; continuity/freshness checks; baseline comparison across regimes |
| P0 | Reject weak current models | Current four runs remain ineligible; no apparent edge hidden by zero-trade cash result |
| P0 | Cost sensitivity, realized depth/impact observations and operating expense attribution | Results survive conservative fee/spread/impact ranges and small-account minimums |
| P0 | Harden deployment: decimal ledger, external audit anchors, tested backups, monitoring | Recovery drill, corruption tests, isolation review and measured service health |
| P1 | Approved paper champion/challenger registry | Separate reproducible review record, forward sample minimum, rollback version; no auto-promotion |
| P1 | Long-history regimes, 24h/7d/30d, block-bootstrap uncertainty, barrier forecasts | Adequate effective independent samples; calibrated errors measured per horizon |
| P1 | 5m/15m event-time feed, WebSockets and order-book replay | Sequence gaps detected; stale feeds halt; point-in-time microstructure features |
| P1 | Verified Trader Intelligence Ledger + Hyperliquid read-only adapter | Separate transfers/P&L/funding, history truncation flags, capital denominators, attribution confidence |
| P1 | Microcap research screen | Configurable cap/age/volume filters; unknown unique traders explicit; sellability/privilege and related-wallet checks; never live |
| P2 | Independent momentum/reversal/shadow/basis hypotheses | Fixed baselines, full failed-run registry, selection-bias corrections and net forward benefit |
| P2 | DefiLlama/Nansen/Arkham/CoinGlass integrations | Explicit license/entitlement/budget approval and provider-specific rate/coverage tests |
| P2 | Skooby subscription entitlements, role-based admin, PostgreSQL/Parquet | Tenant isolation, migrations, billing authorization and retention policies tested |
| P3 | Controlled live execution | Owner-set limits, jurisdiction/account eligibility, exact one-use action approval, restricted credentials, authoritative order reconciliation; separate project review |
| P3 | Boosting/neural/transformer/RL comparison | Reproducibly beats simpler models after costs/compute on untouched data; otherwise reject |

Unavailable in this MVP: a verified profitable strategy, wallet rankings, contract
security certification, automatic strategy promotion, hosted deployment, live
trading, and a continuously running chat automation. There is no implication
that a connected public wallet is successful, safe to copy, or attributable to
one person. Named manipulation signals are risk hypotheses, never proof.
